# ML integration contract

Inspected the Next.js/TypeScript application, PostgreSQL schema and triggers, pg-boss worker, CSV boundaries, deterministic matcher, fixtures, tests and existing documentation before implementation. Original checks: 96 unit, 14 PostgreSQL integration and 4 Chromium tests, lint, typecheck and production build passed after starting Docker. Initial database/browser failures were connection refusals while Docker was stopped. The unchanged 100k command independently produced 69,999 correct allocations in 55.689 seconds; see `artifacts/baseline/reproduced.json`. Historical results are retained separately.

The pure matcher remains the authority for automatic proposals. Its existing bounded candidate search and heuristic scoring are reused with a configurable maximum of 20 candidates (default remains five). The first three heuristic positions therefore remain unchanged. The worker loads a validated, versioned local model once, performs deterministic matching, updates the in-memory invoice balances with proposed allocations, and then ranks exception candidates using shared TypeScript features. ML never creates an allocation. Existing PostgreSQL guards, transactions, retry fencing, reviewer notes and authorization remain authoritative.

Offline Python trains pair classifiers (logistic regression and gradient boosted trees), followed by group-level confidence calibration on separate validation cohorts. Pair classification is chosen because all-negative candidate groups are meaningful, and boosted probabilities can be ranked while a separate calibrator estimates whether the top choice is correct. Exported trees are executed in Node and checked against native Python predictions. The app requires no Python service. Missing, incompatible or disabled models retain the original heuristic path.

Before looking at final test results, freeze the generator, feature schema, candidate policy, model-selection procedure and thresholds in the training metadata. Separate cohort partitions serve model selection, calibration and threshold selection. The final test and withheld-corruption robustness files are read only by the evaluation command. These are synthetic experiments, not production accuracy claims or a human productivity study.
